# NAS 漫画阅读

面向 NAS 的自托管漫画阅读服务。它从只读目录导入漫画，提供书架、元信息管理、用户权限，以及适合手机和横屏设备的分页或滚动阅读。

## 部署

需要 Docker Engine 和 Docker Compose v2。修改 `compose.yml` 中的端口和挂载路径：

```yaml
ports:
  - "3000:3000"
environment:
  COOKIE_SECURE: "false"
volumes:
  - /path/to/manga:/manga:ro
  - ./.data:/data
  - ./.processed:/processed
```

- `/manga`：原始漫画，只读挂载。
- `/data`：SQLite 数据库。
- `/processed`：处理后的阅读图片和上传封面。

三个目录必须互不重叠，`/data` 和 `/processed` 需要允许 UID/GID `1000:1000` 写入。

```sh
mkdir -p .data .processed
sudo chown -R 1000:1000 .data .processed
GIT_BRANCH="$(git rev-parse --abbrev-ref HEAD)" \
GIT_SHA="$(git rev-parse HEAD)" docker compose up -d --build
```

「设置 → 关于」显示分支、HEAD 和镜像构建时间。构建时通过 `GIT_BRANCH`、`GIT_SHA` 传入源码版本；未提供时显示 `unknown`，构建时间自动写入镜像。

打开 `http://服务器地址:3000`，首次访问时创建管理员，再到「设置 → 系统管理」添加导入源和用户。

通过 HTTPS 部署时，将 `COOKIE_SECURE` 设为 `"true"`。反向代理应保留 `Host` 请求头，并允许最多 20 MiB 的封面上传。

## 漫画目录

```text
manga/
└── 漫画标题/
    ├── #001 第一话/
    │   ├── 01.png
    │   └── 02.jpg
    └── #002 第二话/
        ├── 01.jpg
        └── 02.webp
```

一部漫画只有图片而没有子目录时，所有图片会作为同一话导入；存在子目录时，每个含图片的子目录视为一话。章节按名称的字典序排列。章节内图片采用自然排序，文件名中的数字按数值比较（如 `1.jpg、2.jpg、10.jpg`，也适用于 `1_xxx.jpg、2-xxx.jpg、10-xxx.jpg`）。已有章节可通过「刷新全部」纠正图片顺序，复用已处理图片；「仅刷新新增」仍跳过已有章节。

添加导入源时可选择：

- 完全手动：所选目录就是一部漫画。
- 一层扫描：所选目录下的每个子目录是一部漫画。
- 二层扫描：第一层是作者，第二层是漫画。

「仅刷新新增」用于发现新漫画和新章节；「刷新全部」还会检查已有章节的文件变化并修复缺失的处理文件。扫描不会主动删除旧记录，目录改名会被视为新内容。

### 跨页拆分

导入时会先按 EXIF 方向校正图片，再自动处理横向跨页图：宽高比达到 `1.2` 的图片从中间拆为两页；宽度超过高度两倍的超宽图拆为四页。拆分结果按日漫阅读顺序从右向左排列，并完整保留所有像素，不会修改原文件。

跨页拆分默认开启。管理员可在漫画编辑页为单部漫画关闭该选项；保存后平台会在后台重新扫描这部漫画，每张源图完整生成一页，不再拆分。重新开启也会按默认规则重新处理。

平台不会修改或删除原始漫画。移除导入源或删除漫画时，只会按所选操作清理平台记录和派生文件。

## 使用

DeepSeek 标题翻译配置按账号保存在服务器，登录后可跨设备使用；翻译请求由浏览器直接发送到 DeepSeek。

书架支持搜索、作者和标签筛选、排序以及日语/中文标题。管理员可以编辑漫画信息、封面和可见用户。

阅读器支持竖屏单页、横屏日漫单页或双页和纵向滚动模式，并提供章节跳转、画质选择、缩放及触摸手势。横屏单双页偏好按漫画保存在浏览器中，每部漫画首次打开默认双页。阅读页面始终使用黑色背景，主题和阅读偏好保存在浏览器中。

在 iOS 上可通过 Safari 的「添加到主屏幕」安装为 PWA。除 localhost 外，安装和正常使用安全 Cookie 均需要 HTTPS；漫画内容不会离线缓存。

## 备份与维护

查看服务状态和日志：

```sh
docker compose ps
docker compose logs -f
```

完整备份应包括数据库目录、处理目录和原始漫画。为确保 SQLite 备份一致，建议先停止服务：

```sh
docker compose down
# 备份 .data、.processed 和原始漫画目录
docker compose up -d
```

重建容器不会删除挂载目录中的数据。

## 本地开发

需要 Node.js 22 和 npm：

```sh
npm ci
npm run dev
```

前端默认运行在 `5173` 端口，后端运行在 `3000` 端口。提交前可运行：

```sh
npm run build
npm run format:check
```
