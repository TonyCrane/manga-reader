# NAS 漫画阅读

通过 Docker Compose 部署的自托管漫画阅读服务。支持本地目录导入、漫画信息管理、移动端单页阅读、横屏日漫双页阅读和纵向滚动阅读。

## 部署

需要 Docker Engine 和 Docker Compose v2。服务使用单个容器，无需额外数据库。

编辑 `compose.yml` 中的端口及三个挂载路径：

```yaml
ports:
  - "3000:3000"
environment:
  COOKIE_SECURE: "false"
volumes:
  - /path/to/manga:/manga:ro
  - ./data:/data
  - ./processed:/processed
```

素材目录只读；`/data` 保存 SQLite 数据库，`/processed` 保存处理图片和上传封面。三个目录必须互不重叠。容器使用 UID/GID `1000:1000`，数据库和处理目录需要可写。

```sh
mkdir -p data processed
sudo chown -R 1000:1000 data processed
docker compose up -d --build
```

打开 `http://服务器地址:3000`，首次访问时填写邮箱和密码创建管理员。在「设置 → 系统设置」中创建用户、添加导入目录并选择可见用户。

导入界面使用容器内 `/manga` 下的相对路径，也可通过目录浏览器选择；浏览器会显示隐藏文件夹，因此隐藏文件夹本身也能作为导入源。符号链接不会被扫描。迁移主机挂载位置时保留素材根目录内的相对结构。

反向代理应保留 `Host`，转发到容器端口 `3000`，允许至少 20 MiB 的封面上传。HTTPS 部署将 `COOKIE_SECURE` 设为 `"true"`，HTTP 内网访问设为 `"false"`。配置直接写在 Compose 中，无需 `.env`。

## 漫画目录

```text
manga/
└── 漫画标题/
    ├── #001 第一话/
    │   ├── 01.png
    │   ├── 02.jpg
    │   └── 03.webp
    └── #002 第二话/
        ├── 01.jpg
        └── 02.jpg
```

只有图片、没有子目录的漫画被视为一话，章节初始名称为漫画目录名。有子目录时，各含图片的子目录作为一话，漫画根目录的图片不参与章节导入。扫描会跳过空目录和导入源内部的隐藏子目录；直接选为导入源的隐藏文件夹仍可正常扫描。

章节和图片均使用名称的字典序排序，不使用自然数字排序。例如 `1.jpg、10.jpg、2.jpg` 按该顺序排列；固定宽度的编号如 `01、02、10` 可以保持数字顺序。

### 导入方式

| 方式     | 所选目录结构                                   |
| -------- | ---------------------------------------------- |
| 完全手动 | 所选目录就是一部漫画                           |
| 一层扫描 | 所选目录下的子目录分别是漫画                   |
| 二层扫描 | 第一层子目录名作为标签，第二层子目录分别是漫画 |

导入源会持久保存，可在目录设置中修改路径和扫描方式。后续点击「刷新」选择范围：

- **仅刷新新增**：发现新漫画、新章节；已有章节不枚举图片、不检查文件变化，也不检查处理文件。适合日常更新。
- **刷新全部**：检查所有章节的文件名称、大小和修改时间，处理新增或变化图片，复用已有结果并补回缺失输出。若整话的统一宽高比发生变化，重新生成需要调整黑边的页面。

一次运行一个导入任务，目录扫描和文件检查并发执行，图片通过 Sharp 原生线程池处理（按可用 CPU 数量并发 1–4 张），进度写入合并，章节数据通过事务发布。设置页面显示文件处理进度、当前章节和失败原因。完成结果在刷新或重新进入设置页面后隐藏，可在各目录设置中查看最近 20 次导入记录。失败或中断后可以重新刷新；已完成且未变化的章节直接跳过。

目录标题作为漫画和章节的初始名称。漫画详情中可以编辑漫画标题、作者、发布时间、导入时间、标签与各话标题。刷新保留这些修改。未手动填写的字段显示为占位提示；清空手动标题后恢复扫描名称。标签支持回车添加和逐项移除。封面默认为第一话第一页，在「编辑信息 → 更换封面」中上传图片或切换章节选择页面，只加载当前章节的图片。书架和详情页按需生成并复用最大 `480×640` 的 WebP 封面缩略图，阅读图片不受影响。

扫描不会主动删除已导入的漫画或章节。移除导入源仅停止从该源刷新，不删除已有内容。管理员可从「编辑信息 → 删除漫画」单独删除，也可在书架进入批量管理后选择并删除多部漫画；删除会清除平台记录、处理图片、缩略图和上传封面，保留所有原文件。若仍位于导入源中，下次刷新会重新导入。目录重命名视为新的漫画或章节。旧的处理文件保留，以免影响正在阅读的页面及手动选择的封面。

### 图片处理

- 接受 JPG/JPEG、PNG、WebP、AVIF、TIFF 和 GIF；多帧格式导入第一帧。
- 根据 EXIF 方向校正图片。宽度大于高度时视为双页，从中间拆分，先右页、后左页；宽度大于高度两倍的超宽图视为四页，等分后从最右页到最左页排列。不能整除时会完整保留所有像素。横向插画也适用这些规则。
- 按每话拆分后最窄页面的宽高比补齐上下黑边，不在左右添加黑边，不裁掉原画面。超长图导致单侧补边超过 10000 像素时改用等尺寸黑色画布合成；像素取整可能产生不到一个像素的比例差异。
- 「原图」画质为保持原分辨率、经方向校正、拆页和补边的无损 PNG；不是未处理的源文件。
- 「优化」画质为 WebP，宽度最多 1600 像素；为兼容 WebP 格式，超长页面高度最多 16000 像素且不裁切，质量 85。小于 300 KiB 且宽度不超过 1600 的源图使用无损 WebP。
- 所有输出写入 `PROCESSED_DIR`，不修改素材。无损版本可能比源 JPEG 占用更多空间。
- 章节全部处理成功后更新其页面列表；处理失败时保留该章节先前可用的页面。

## 阅读

书架展示封面、标题和话数，支持搜索作者、标签后筛选以及漫画名称搜索。可按名称、话数、导入时间或发布时间排序，排序方向通过独立按钮切换，多个标签按“与”筛选，未填写的发布时间排在最后。书架和设置导航固定在底部居中。点击漫画打开章节目录，可切换正序或倒序并从任意话开始阅读；详情页标签可直接返回书架并应用对应标签筛选。

### 日漫模式

- 竖屏单页，横屏双页；双页前页在右，后页在左，两页紧贴。
- 点击屏幕左侧下一页，右侧上一页，中间显示或隐藏菜单。
- 向右滑动下一页，向左滑动上一页。键盘左方向键下一页、右方向键上一页，空格或 Escape 切换菜单。
- 双指捏合缩放，放大后单指拖动；缩小至原尺寸以下，松手后回到原尺寸。
- 横屏默认 `1/2、3/4` 配对。双指轻点或菜单中的「跨页配对」切换为 `空白/1、2/3、4/5`。首尾不足两页时补纯白页。
- 到达章节边界时直接进入相邻章节，顶部短暂显示章节提示；每话单独配对，不跨章节拼接。

### 滚动模式

所有章节连续纵向排列，图片按需加载。菜单提供当前话进度、画质、页码开关和章节选择。切换章节或拖动进度条可直接定位页面。

阅读区域始终黑色。书架亮暗主题和阅读设置保存在当前浏览器。平台不保存阅读历史。相邻页面与下一话开头自动预加载，图片响应使用 private, no-store，权限变更后重新请求会立即校验。

## iOS 主屏幕应用

使用 Safari 通过 HTTPS 打开服务，选择「分享 → 添加到主屏幕」。主屏幕应用使用独立窗口和安全区域适配，支持竖屏、横屏切换。

Service Worker 只缓存公开应用框架和静态资源，不离线缓存漫画或登录接口。漫画阅读需要服务器在线；退出登录会撤销会话，但不会清除已显示在浏览器内存中的图片。

## 访问控制

账号仅保存邮箱和密码凭据，不开放注册，不需要邮箱验证。密码长度为 8–128 个字符，通过随机盐和 scrypt 散列存储。管理员创建用户或重置密码后，用户必须先修改初始密码才能访问内容。所有用户均可在设置中修改自己的密码。

管理员可管理用户、管理员身份及导入目录，系统保留至少一名管理员。每个导入目录独立选择可见用户，管理员同样受该限制；属于多个目录的漫画对任一目录授权的用户可见。普通用户只能阅读，不能导入或编辑漫画。移除目录后保留漫画及当时的授权，重新导入后使用当前目录授权。

登录会话有效期为 30 天，使用 HttpOnly、SameSite=Strict Cookie；退出登录撤销当前会话，修改或重置密码会撤销该账号已有会话。漫画详情、封面及图片均检查用户可见权限，登录接口限制请求频率。互联网部署使用 HTTPS。

## HTTP API

除健康检查、初始化状态、首次初始化和登录以外，所有接口需要会话 Cookie。JSON 请求使用 `Content-Type: application/json`。

| 方法与路径                      | 用途                                                                                 |
| ------------------------------- | ------------------------------------------------------------------------------------ |
| `GET /api/setup`                | 是否需要创建首个管理员                                                               |
| `POST /api/setup`               | `{ "email": "邮箱", "password": "密码" }`                                            |
| `POST /api/account/password`    | `{ "currentPassword": "当前密码", "password": "新密码" }`                            |
| `GET /api/users`                | 管理员查看用户                                                                       |
| `POST /api/users`               | `{ "email": "邮箱", "password": "初始密码", "isAdmin": false }`                      |
| `PATCH /api/users/:id`          | `{ "isAdmin": true }`                                                                |
| `POST /api/users/:id/password`  | 管理员重置密码，`{ "password": "初始密码" }`                                         |
| `GET /api/health`               | 容器健康检查                                                                         |
| `POST /api/login`               | `{ "email": "邮箱", "password": "密码" }`                                            |
| `GET /api/session`              | 检查当前会话                                                                         |
| `POST /api/logout`              | 注销会话                                                                             |
| `GET /api/manga`                | 漫画列表                                                                             |
| `DELETE /api/manga`             | 批量删除，`{ "ids": ["漫画 ID"] }`，一次最多 500 部                                  |
| `GET /api/manga/:id`            | 漫画详情、章节和页面                                                                 |
| `PATCH /api/manga/:id`          | `{ "title": "标题", "author": "作者", "published": "2026-01-01", "tags": ["标签"] }` |
| `DELETE /api/manga/:id`         | 删除平台中的漫画记录与派生图片，保留素材                                             |
| `PATCH /api/chapters/:id`       | `{ "title": "章节标题" }`                                                            |
| `GET /api/manga/:id/cover`      | 当前封面；`?size=small` 返回最大 `480×640` 的缩略图                                  |
| `PUT /api/manga/:id/cover`      | `{ "pageId": "页面 ID" }`，从本漫画选择封面                                          |
| `POST /api/manga/:id/cover`     | multipart/form-data，字段 `cover`，最大 20 MiB                                       |
| `GET /api/directories?path=.`   | 浏览素材根目录内的文件夹                                                             |
| `GET /api/sources`              | 持久导入源                                                                           |
| `POST /api/sources`             | `{ "path": ".", "mode": "manual 或 one 或 two", "userIds": ["用户 ID"] }`            |
| `PATCH /api/sources/:id`        | 修改路径和扫描方式，字段与添加导入源相同                                             |
| `GET /api/sources/:id/jobs`     | 指定目录最近 20 次导入记录                                                           |
| `DELETE /api/sources/:id`       | 移除导入源                                                                           |
| `POST /api/sources/:id/refresh` | `{ "mode": "all" 或 "new" }`，默认 all，返回任务 ID                                  |
| `GET /api/jobs`                 | 最近 20 个任务及处理进度                                                             |
| `GET /media/*`                  | 受会话保护的处理图片                                                                 |

漫画信息 PATCH 的 `created` 字段接受 ISO 日期时间，用于修改导入时间。漫画信息 PATCH 支持只提交变化字段，未提交字段保持原值。漫画及章节的 `title` 设为 `null` 或空字符串时恢复扫描名称。

## 运行与维护

```sh
docker compose logs -f
docker compose ps
docker compose down
docker compose up -d --build
```

备份时先停止服务，再同时备份 `DATA_DIR` 与 `PROCESSED_DIR`；源漫画目录单独备份。恢复时保留素材根目录内的相对结构。SQLite 数据包含漫画信息、导入源、任务和登录会话。

前端使用 React、TypeScript、React Router 和 Vite，后端使用 Node.js、Express、SQLite 和 Sharp。代码按页面、阅读器、导入处理及 API 分模块组织。

Node.js 22 环境也可直接运行：

```sh
npm ci
npm run build
MANGA_DIR=/path/to/manga npm start
```

本地双服务运行使用 `npm run dev`：Vite 监听 5173，代理 API 与图片到后端 3000。通过 `MANGA_DIR=/本机素材路径 npm run dev` 指定素材位置。`npm run check` 执行 TypeScript 静态检查。

代码格式统一使用 Prettier（2 空格缩进、80 字符目标行宽）。`npm run format` 格式化代码，`npm run format:check` 检查格式。
